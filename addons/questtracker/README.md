---

A quest tracker in the style of World of Warcraft's. When you accept a quest it's tracked
automatically, and an on-screen list shows each tracked quest's **next step**: who to talk to,
where (zone and map grid), what to trade, which key item you get. Finished steps disappear, so the
list only ever shows what to do now.

`/addon load questtracker`, then `/qt` for the journal.

## The tracker

- One line per tracked quest: its name, the step count (`4/6`) and the current step. A `>` marks
  steps you can do in the zone you're in.
- **What the step needs:** items to trade and key items to have, each with a green check if you're
  set or an orange cross if not. Items show how many you're carrying (`1/3 Rabbit Hide`), and
  note when the rest is in another bag (`2 in another bag`), since trades take only what's in
  your inventory.
- **Kill counters:** steps that need kills show a running count (`Kills: 37/100`) and finish
  themselves when it's reached. The count follows the server's rule for that quest: Blade of Darkness
  counts only melee killing blows with the Chaosbringer equipped. The server keeps its own hidden
  count, so if you started before installing, set yours with the -10 / -1 / +1 / +10 buttons under
  the step in the journal.
- **Click the QUESTS header** to minimize the tracker to that one line; click it again to restore.
- **Click a quest's name** to fold it. **Right-click** it for *Step done*, *Undo a step*, *Untrack*
  and *Open journal*.
- It sits on a themed box so it stays readable over any scenery. **Right-click the tracker's
  background** to set how solid the box is (0 for none), lock it, open the journal or hide it.
- Drag it anywhere; lock it with the right-click menu or `/qt lock`. Width, background and how many
  quests it shows are also on the journal's Options tab.

## The journal (`/qt`)

Every quest in your log, grouped by area, with a **Track** checkbox. Pick one to see all its steps
(done, current and upcoming), who starts it, and its rewards.

- **Already partway through a quest?** Each step has a checkbox: tick the last step you've done and
  everything before it is marked done too; untick to go back. Quests the addon finds already in
  progress are marked *(check progress)* until you do.
- **Add a quest you're on:** type part of its name in the box at the top of the list and click `+`.
  Useful right after installing, before the server has sent your quest log. Once it does (next
  time you zone), the server's log is what counts.

The **Options** tab holds auto-tracking, the tracker's visibility, width, background, how many
quests it shows, and the theme.

## How it knows

The addon only reads what the game already tells your client:

- **Your quest log.** The server sends it at login, when you zone, and whenever a quest is added or
  completed. New quests are tracked automatically (quests already in your log the first time are
  listed in the journal, but not tracked until you tick them). Completed quests drop off with a
  "Quest complete" message.
- **Cutscenes.** Each step lists the cutscene that finishes it. When that cutscene plays (zone +
  cutscene number), the step is done.
- **Key items.** If a step ends with a key item, holding it marks that step (and everything before
  it) done.

The server doesn't send quest progress itself, so progress is saved per character. If you install
the addon partway through a quest, tick the steps you've done in the journal. The addon can't read
your quest log from the game's memory (Ashita has no API for it), so it waits for the server to
send it: zone once after installing, or add your quests by hand in the journal.

## Where the steps come from

- `data/quests.lua` is generated by `tools/build_quests.py` from PhoenixXI's own quest scripts
  (LandSandBoat, GPL-3.0), so steps match how Phoenix actually runs each quest: 577 quests, 383
  with steps (137 multi-step). Quests coded the older way, inside NPC scripts, have no step list yet;
  the tracker shows who starts them.
- `data/overrides.lua` and `data/overrides_jobs.lua` hold hand-written steps for key quests, with
  clearer wording and gotchas like the Ninja quest's "go back to Ensetsu". So far: every advanced job
  unlock (Paladin, Dark Knight, Beastmaster, Bard, Ranger, Samurai, Ninja, Dragoon, Summoner, Blue
  Mage, Corsair, Puppetmaster), researched from the server's quest and NPC scripts. Some steps can't
  be detected (a hidden kill counter, an NM fight with no cutscene, collecting weather lights); mark
  those done yourself and the next detectable step catches up.

To rebuild after a server update:

```
git clone -b live https://github.com/phoenixffxi/Phoenix phoenix
pip install pyyaml lupa
python tools/build_quests.py --server phoenix
```

## Commands

| Command | |
|---|---|
| `/qt` | open or close the journal |
| `/qt show` / `hide` | the on-screen tracker |
| `/qt track <quest>` / `untrack <quest>` | by (part of) its name |
| `/qt done [quest]` / `undo [quest]` | step done / back one step (first tracked quest if no name) |
| `/qt min` | minimize or restore the tracker |
| `/qt auto` | track new quests automatically, on or off |
| `/qt lock` | lock or unlock the tracker's position |
| `/qt theme <name>` | Farplane9, Farplane, Phoenix, Umbrella, Midnight, Classic |

## For reviewers

### What it reads

**Incoming packets.** It only listens; the packets are never changed or blocked.

| Packet | Used for |
|---|---|
| 0x056 (quest / mission log), quest ports 0x50-0x80 and 0x90-0xC0 | which quests are current and which are completed |
| 0x032 / 0x034 (event start) | the zone and cutscene number, to tick off the step that cutscene finishes |
| 0x028 (action), category 1 from your own character | your melee hits, for a melee-only kill counter (Blade of Darkness) |
| 0x029 (battle message) with message 6 ("defeats") | kill counters |

**Client memory, through Ashita's API:**
- your key items (`IPlayer:HasKeyItem`), for steps that hand out or need a key item;
- item counts in your bags, only for items a tracked quest's current step needs;
- your main weapon, for a weapon-specific kill counter;
- your zone and party member ids (whether a kill was yours or your party's), and the defeated mob's name.

### What it writes

- Its own settings file, through Ashita's settings library: tracked quests, step progress, kill
  counts and window options.
- Notices in your own chat log (new quest, next step, quest complete). Nothing is sent to any chat
  channel.

### What it does NOT do

- **No outgoing packets.** It has no `AddOutgoingPacket` call or any other packet injection.
- **No commands.** No `QueueCommand` or automated chat or actions; no targeting.
- **No changes to incoming data.** No incoming packets are modified, blocked or injected.
- **No network or file access** beyond Ashita's settings file.
- **No hidden information:** quest progress isn't sent by the server, so steps are inferred from
  what the client already shows (cutscenes, key items, kills) or ticked by the player.

### Data tables

`data/quests.lua` is generated by `tools/build_quests.py` from PhoenixXI's public server repository
(the interaction-framework quest scripts under `scripts/quests/`, the NPC data and the zone and item
enums); `tools/quest_catalog.py` supplies quest names, start NPCs and era filtering, and
`tools/grid.py` the map grid. `data/overrides.lua` and `data/overrides_jobs.lua` are hand-written
step lists for the job unlock quests, taken from the same server scripts. To rebuild:

```
git clone -b live https://github.com/phoenixffxi/Phoenix phoenix
pip install pyyaml lupa
python tools/build_quests.py --server phoenix
```
